# Ace2 RAG 第一轮优化

日期：2026-10-04。基线：应用内 CPU 约 13–14 token/s；检索约 0.4 秒，Hive 问答首 token 约 6.5–8 秒。详细基线见 `ace2-native-performance.md`。

## 本轮改变

1. Markdown 分块识别反引号/波浪线代码围栏，不再把代码中的 `#` 当成标题。普通代码块允许超过 300 字符的正文目标；很长的代码在约 1,200 字符处按完整行分组，每组保留语言和围栏，代码行不丢失。未闭合围栏只补格式闭合，不补代码。
2. 普通 RAG 默认简答、最多三点，以 `[1]` 等编号引用。详细/逐步请求保留步骤解释，不强制三点。长代码只给模型短节选，原文不经模型转写；参考内容总字符预算约 1,200、每条最多 600（不是精确 token 上限）。删除重复来源前缀和完整文件名转写要求，保留资料/指令边界并转义伪造 reference 标签。
3. 回答下方新增“知识库原文”折叠区，显示命中章节、完整索引代码及 Obsidian 打开入口。从缓存补齐相关章节、合并重叠内容；来源编号对应检索顺序，重复章节合并显示。同名笔记通过文档 ID 区分，不混合不同文件。展开资料受 32,000 字符上限约束，超出时标注截断，完整文件仍可在 Obsidian 打开。
4. 编号引用绑定各回答点自己的参考资料；未知编号、指向错误资料、未见于资料的行内代码/部分依赖、API、版本标识会触发保守回退。无法校验的摘要显示简短提示及原文面板，不再复制或自动朗读数万字资料。原文和 RAG 回答不参与意图执行。
5. 增加分块版本检查：旧索引不清空、不改数据库 schema。下一次**用户手动同步**时按新规则逐篇重建，事务成功前保留该篇旧索引；全量成功才记录新版本，失败文件下一次可重试。若部分失败，目前下次同步会重复处理已成功的文件，以换取简单且安全的版本一致性。

## 验证情况

先添加失败回归，旧实现出现五个失败：拆码、代码标题误识别、冗长提示词要求、错误引用、虚构依赖。随后补了互换引用的失败用例，再修复。

最终 **46 项 JVM 测试全部通过**，`:app:assembleDebug` 成功。覆盖长代码逐行无丢失、不同长度围栏、未闭合围栏、短事实、提示词预算/资料边界、来源编号/去重/同名文档隔离、保守摘要回退、旧索引版本失效等。

固定合成 Hive 资料：旧 RAG 提示词 **607 字符**，新 **479 字符**，减少约 **21.1%**；关键事实与 `Hive.initFlutter()`、`Hive.openBox`、`hive_flutter: ^1.1.0` 仍保留。这是相同资料的字符串长度对照，**不是实际 token、首字时间或 token/s 的改善证明**。较长资料的模型输入被节选，但原文面板保留独立的资料快照。

本轮未更改 CPU/GPU/线程/量化设置，未安装、重启或操作手机应用，也未执行知识库同步。手机在验证时已无 ADB 连接。因此 UI 展开/复制/链接、语音全链路、实际 tokenizer 与真机回答质量/耗时尚待确认。

## 复现

```sh
RAG_PROMPT_FIXTURES_DIR="$PWD/build/rag-prompt-fixtures" ./gradlew :app:testDebugUnitTest :app:assembleDebug --rerun-tasks
```

上面会生成合成问答的完整前后提示词，包含相同系统提示、问题和禁用思考前缀。用于比较 token 数的工具必须使用项目固定的 llama.cpp 版本：

```sh
# 使用当前 Android runtime 的 Ninja，构建官方 tokenizer 工具。
ninja -C build/native-runtime/runtime llama-tokenize
# 手机重新连接后执行；只加载词表，不加载模型权重、不生成、不安装、不重启。
bash Script/probe_rag_prompt_tokens.sh
```

之后，在允许覆盖安装测试版并重启应用后，再运行 `Script/probe_app_generation.py` 对照相同问题。比较检索命中、首字时间、总耗时、正文长度、引用准确率与回退率，不只比较 token/s。不要运行会卸载目标应用的 instrumentation runner。

## 仍需注意

- 校验是保守的字符串规则，不是逐句语义真实性证明；正确但改写较大的答案也可能被回退。
- 新分块索引只有手动同步后才生效；旧索引仍可使用，但已被拆开的代码不会仅靠升级 APK 自动恢复。
- 极长代码单行仍保持完整；字符预算不等于 embedding 的 512-token 窗口，现有 embedding 截断行为尚未改成 token-aware 分块。
- 本轮没有加入额外 reranker、改变 BGE 查询前缀/相似度阈值或实现系统前缀 KV 复用；这些需各自建立命中率与真机性能对照后再做。
