# RAG 零命中后普通聊天被拒答：会话隔离修复

日期：2026-10-06。

## 症状与代码证据

用户截图：问题“你是什么星座”，界面标明“本轮未引用知识库 · 0 个命中”，模型却回答“知识库资料不足”。普通聊天不应受上一轮资料问答的“只依据资料”限制。

旧 MainViewModel 仅在当前轮有 RAG 命中时清空 native KV；系统提示词只在 UI 第一轮或当前轮有 RAG 命中时注入。native-lib.cpp 会跨轮保留 KV。因此 RAG 后的零命中普通聊天同时缺少缓存隔离和普通系统提示词重注入。默认全局系统提示词不含这项资料限制，零命中分支也没有直接注入它。

## 复现与验证边界

提取生产代码真正使用的 `ConversationSession` 和 `ConversationPromptBuilder`，先保留旧请求行为。记录型引擎按 native 跨轮追加/清空输入的机制保存上下文，连续请求“介绍 Hive → 你是什么星座”。4 个用例中 2 个失败：普通聊天继承 RAG 限制，以及清空 native 后 UI 不是第一轮时丢失系统提示词。

该反馈循环验证的是**生产请求链路的上下文隔离**，记录型引擎模拟了截图中的拒答。不是在真实 MiniCPM5-2B 上生成出来的逐字复现；手机上的具体输出、用户自定义系统提示词仍待真机确认。

## 修复

- 仓储层记录实际 native 会话模式，不再仅靠聊天列表中的用户消息数决定上下文初始化。
- CHAT ↔ RAG 切换时清空推理缓存，重新注入当前模式的系统提示词；每次 RAG 仍保持资料自包含。CHAT → CHAT 保留原有多轮上下文。
- 状态查询与只查原文未调用模型时，不改变模型会话状态。首次真正推理、模型加载/释放、显式重置后，都会重新初始化系统提示词。
- 中断、异常或 native 错误结果使上下文失效，下次请求不会继承未完成内容。重置失败不继续生成。
- 把“判定会话 → 重置 → 构造提示词 → 推理”放在同一把协程互斥锁内，避免其他请求插入。模型加载/释放/手动重置走同一锁；停止生成仍直接调用 native 的原子停止标志，不等待这把锁。
- 同一 repository 上的外部 API 请求与 UI 请求也隔离模式；外部连续请求仍沿用现有的连续上下文行为。外部 API 多客户端之间的独立 session 管理不在本次范围内。

仅清理运行时推理缓存，不删除聊天记录、模型、知识库、索引或用户设置。切回普通聊天不再保留上一轮 RAG 推理上下文；依赖前一轮资料的省略式追问属于后续多轮检索设计，不能假装已经完整支持。
